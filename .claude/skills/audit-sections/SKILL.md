# 섹션 스타일 감사

이 프로젝트의 섹션 규격은 "하나를 바꾸면 전부 바꾼다" 가 원칙이다 (`src/sections/CLAUDE.md` 4절).
사람이 8개 CSS 파일을 눈으로 대조하면 반드시 빠뜨리는 게 나온다 — 과거에 Gallery·PhotoDrop 만
430px 오버라이드가 없어 타이틀이 커 보였던 사고가 그 예다. 이 스킬은 그 대조를 스크립트에 맡긴다.

## 실행

```bash
node .claude/skills/audit-sections/scripts/audit-sections.mjs
```

프로젝트 루트 어디서 실행해도 된다 (스크립트가 자기 위치 기준으로 루트를 찾는다). 종료 코드는 위반이 있으면 1.

스크립트는 기준값을 **자기 안에 두지 않는다.** 매번 아래 문서를 읽어서 기준으로 쓴다:

| 기준 | 읽는 곳 |
|---|---|
| 섹션 루트 / `__title` / `__subtitle` 정본 | `src/sections/CLAUDE.md` 3·4·5절의 ```css 블록 |
| 허용 색상과 표기(대소문자) | `THEME_COLORS.md` 에 등장하는 모든 hex |
| 허용 폰트 | `public/index.html` 의 Google Fonts 링크 |

그래서 정본을 바꾸고 싶을 때는 **문서를 먼저 고치고** 스크립트를 돌리면, 아직 안 따라온 섹션이 전부 나온다.

## 결과 읽는 법

출력은 세 묶음이다.

- **섹션 정본 대조** — 섹션마다 `.block`, `.block__title`, `.block__title:lang(en)`, 430px 안의 두 오버라이드,
  (있으면) `.block__subtitle` 을 정본과 선언 단위로 비교한다. `prop: 실제 → 정본` 형식으로 나온다.
  `__title` 이 없는 Hero / ThankYou 는 예외 섹션이라 건너뛴다.
  브레이크포인트가 430px 외에 있거나, 미디어쿼리가 파일 끝에 모여 있지 않거나, 순서가 `430px → prefers-reduced-motion` 이 아니면 함께 알린다.
- **색상** — `src/` 아래 모든 CSS 의 hex 를 모아 `THEME_COLORS.md` 에 **같은 표기로** 있는지 본다.
  `#c9a77c` 처럼 소문자로 쓴 것은 "표기 불일치" 로, 문서에 아예 없는 값은 "없는 색" 으로 구분한다.
- **폰트** — `font-family` 에 로드하지 않는 폰트가 있는지, `Roboto` 를 라벨 서명(letter-spacing / uppercase) 없이 본문에 썼는지,
  `Dancing Script` 가 로딩 화면 밖으로 새지 않았는지 본다.

`✗` 는 고쳐야 하는 위반, `!` 는 판단이 필요한 주의다.

## 위반을 고칠 때

1. **한 섹션만 고치지 않는다.** 같은 항목이 여러 섹션에서 나오면 전부 같은 값으로 맞춘다.
   반대로 한 섹션만 다르게 나왔는데 그 값이 더 낫다고 판단되면, 정본 문서(`src/sections/CLAUDE.md`)를 먼저 고친 뒤 나머지를 따라오게 한다. 정본과 코드가 어긋난 채로 두는 것이 최악이다.
2. **색 표기 불일치**는 `THEME_COLORS.md` 의 표기로 바꾼다 (코어 5색은 대문자, 회색 `#e0e0e0` 등은 소문자 그대로).
   문서에 없는 색이 나왔다면 새 색을 문서에 추가하거나 기존 색으로 교체할지 사용자에게 묻는다 — 새 색은 임의로 만들지 않는다 (`theme-concept.md` 2절).
3. **`!` 주의 항목**은 의도적일 수 있다 (예: AboutUs 의 430px 블록이 여러 개인 것). 사용자가 스타일 정리를 요청한 맥락이 아니면 보고만 하고 건드리지 않는다.
4. 고친 뒤 스크립트를 다시 돌려 `위반 0건` 을 확인하고, 마지막으로 `npm run build` 로 빌드·린트를 통과시킨다.

## 스크립트가 못 잡는 것

- JSX 쪽 규칙: `lang={language}` 누락, `<h2>` 대신 다른 태그, `section-divider` 재정의. 이건 `grep -n "lang={language}" src/sections/*.tsx` 로 따로 본다.
- 문구 하드코딩 (`translations.ts` 밖의 사용자 문구).
- 그림자·그라데이션 방향 같은 `theme-concept.md` 4절의 은유 규칙.

이런 항목이 의심되면 결과 보고에 "스크립트 범위 밖" 이라고 명시하고 별도로 확인한다.
